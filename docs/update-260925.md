# 2026-09-25 .NET 基础实现记录

## 已实现

- 建立 .NET 10 Windows Forms 应用和根目录解决方案。`MiniDeepCoolDigital/` 与 `MiniDeepCoolDigital.Tests/` 是根目录下同级的应用和测试项目；解决方案、SDK 配置和文档留在根目录。应用以 `ApplicationContext` 常驻托盘，不创建可见主窗口；用命名互斥量限制单实例。项目直接依赖 `LibreHardwareMonitorLib` 0.9.6 与 `HidSharp` 2.6.4，不需要 Rust 或独立传感器进程。
- 托盘提供 CH270 设备选择与重新扫描、GPU 来源选择、CPU/GPU 模式、1/3/5/10 秒更新频率、暂停/恢复数显更新、当前用户开机启动、传感器诊断和退出。参考 [PowerToys 的 Windows 原生托盘菜单做法](https://github.com/microsoft/PowerToys/blob/main/src/runner/tray_icon.cpp)，`NotifyIcon` 保留图标与消息，右键用 Win32 弹出菜单 API 绘制菜单及子菜单，交由 Windows 呈现系统样式；操作仍复用原来的菜单事件。用户已确认新菜单外观和操作正常。
- 当前用户配置写入 `%LOCALAPPDATA%\MiniDeepCoolDigital\config.json`，采用临时文件及替换操作；默认更新频率为 5 秒，无效值也回退到 5 秒。已有配置中明确保存的 1/3/5/10 秒值继续生效。开机启动改为当前用户登录计划任务，使用交互会话和最高可用权限，不再由无法提升权限的 Run 项启动。任务状态从 Windows 实际任务读取；启用或关闭时清理旧版同名 Run 项。应用清单请求管理员权限。
- 使用 `LibreHardwareMonitorLib` 仅打开 CPU/GPU 硬件组，按传感器类型和语义名称映射温度、功耗、使用率、频率。多 GPU 默认优先独显，也可在托盘指定 GPU。关键指标缺失或报告不可信的零值时，不会写入伪造数据。
- 独立实现 CH270 的 64 字节 CPU 频率页、GPU 页报文及校验；按 VID `0x3633`、PID `0x0016` 与 HID 输出报告长度枚举设备。协议字段参考[上游 CH 第二代映射](https://github.com/Nortank12/deepcool-digital-linux/blob/main/device-list/tables/ch-series-gen2.md)，未复制上游源码。
- 后台只有一个顺序更新工作者。所选周期同时控制传感器读取和 HID 写入；菜单更改立即通知工作者，设备每 10 秒兜底重扫。异常在托盘状态中显示，HID 句柄会释放并在下一次更新时重试。
- 统一精简托盘状态和诊断文案，移除不影响操作的括号说明；原始传感器名称仍保留在诊断列表中，供排障时核对。
- 使用 MSTest 官方测试框架验证报文字段与校验、无效温度、频率和模式配置；测试由 `dotnet test` 发现和运行。原控制台检查及其手动硬件探针入口已移除。

## 本机验证

- 在仓库根目录直接运行 `dotnet build`：成功，0 警告、0 错误，应用产物位于 `MiniDeepCoolDigital/bin/Debug/net10.0-windows/`。直接运行 `dotnet test` 发现并通过 8 个 MSTest 测试。
- 迁移前的手动诊断命令曾只读枚举到一台 CH270 DIGITAL，并得到完整的 RTX 5080 GPU 四项数据；一次显式 GPU 单帧 HID 写入成功，用户确认 CH270 屏幕正确显示 GPU 四项。手动诊断命令已随旧控制台检查项目移除。
- 同一只读探针中，Ryzen 7 9800X3D 的 CPU 温度、功耗和平均频率返回 `0`，预热后仍然如此；目前 CPU 模式会提示指标不可用并停止写入。当前进程为普通用户权限，系统查询不到 PawnIO 服务；这提示低层驱动可能尚未就绪，但还不能排除硬件与库版本的兼容性问题。没有手动安装或更改驱动。
- 再次读取原始传感器并预热 1 秒后，CPU Total 使用率约为 16–21%，但 `Core (Tctl/Tdie)` 温度、`Package` 功耗、`Cores (Average)` 频率仍全为 0；`PawnIo.IsInstalled` 返回未安装，系统服务查询也找不到 PawnIO。应用诊断窗口现在显示 PawnIO 状态；CPU 采样失败时会说明缺少驱动的可能性。LibreHardwareMonitor 的[实现](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/PawnIo/PawnIo.cs)和[官方界面](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitor.Windows.Forms/UI/MainForm.cs)表明底层读取依赖 PawnIO，界面在缺失时会提示安装。尚未安装驱动，因此不能宣称 CPU 四项已可用。
- 用户随后自行安装了 PawnIO 2.2.0.0。服务查询显示驱动正在运行，但普通权限进程再次预热采样后，CPU 温度、封装功耗、平均频率仍为 0，只有使用率可用。当前进程的管理员组在令牌中未启用，而 [PawnIO 驱动 INF 的设备权限](https://github.com/namazso/PawnIO/blob/master/PawnIO/PawnIO.inf.in)只授予 SYSTEM 和管理员组；需要由用户在提升权限的进程中复测才能确认完整 CPU 数据。诊断窗口现同时显示驱动版本与进程权限，并针对这种情况给出提示。
- 新增 `README.md`，说明 PawnIO 是 CPU 底层传感器的运行依赖，附[官方网站](https://pawnio.eu/)及[官方发布页](https://github.com/namazso/PawnIO.Setup/releases)，并说明程序不会安装驱动。应用现通过清单在手动启动时请求管理员权限，登录任务也以最高可用权限运行。
- 用户授权后，以管理员权限运行一次临时硬件探针。探针报告 PawnIO 2.2.0.0、管理员权限，9800X3D 原始传感器读到 `Core (Tctl/Tdie)` 50.88°C、`Package` 52.19W、`CPU Total` 17.45%、`Cores (Average)` 4746MHz；随后形成 CPU 样本 50.63°C、47.33W、13.7%、4278MHz，并完成一次 CH270 CPU HID 单帧写入。探针测试通过，用户确认屏幕正确显示四项。临时探针源码已移除。
- 托盘进程启动后持续存活 3 秒的冒烟检查通过；随后结束了该检查进程。后来以管理员权限对真实 CH270 运行持续更新探针：CPU 1 秒、GPU 3 秒、CPU 5 秒、GPU 10 秒档均按所选周期写入；切换模式立即写入新模式帧，暂停后 2 秒无写入，恢复后立即写入。该探针只用于验证，源码已移除。用户在真实托盘中检查 CPU/GPU 切换、四档更新频率和暂停/恢复，确认屏幕与菜单状态均正常；暂停一段时间后 CH270 会自动熄屏。
- Windows 登录计划任务经过一次管理员权限的临时注册、查询与删除实测，全部通过，测试后任务不存在。官方 MSTest 包含计划任务 XML 的权限、登录触发、进程路径和单实例策略检查；当前共 9 项通过。尚未进行真正注销/重新登录测试。

## 当前限制与后续验证

1. **CPU 权限与常驻启动**：管理员权限下已读到完整 CPU 样本，普通权限下仍无法读取 CPU 温度、功耗和频率。应用和登录计划任务已配置权限，仍需注销/登录检验实际自启动。当前实现不会把零值显示成真实温度/功耗/频率。
2. **托盘开关是“暂停/恢复更新”**：暂停后 CH270 本机自动熄屏，程序不发送未经验证的硬件熄屏命令。
3. **页面验证范围**：CPU/GPU 四项及连续更新已由用户在 CH270 上确认。设备拔插、睡眠恢复、Explorer 重启以及官方软件同时运行仍需逐项实测。
4. **发布与性能**：尚未做发布包，也未测量 .NET 进程的私有工作集、空闲 CPU 或与官方软件的对比。

## 开发命令

在已通过 mise 配置 .NET 10 SDK 的终端中，从仓库根目录运行：

```powershell
dotnet build
dotnet test
dotnet run --project MiniDeepCoolDigital/MiniDeepCoolDigital.csproj
```

最后一条请在管理员终端执行；直接启动构建产物时会请求提权。NuGet 与 .NET CLI 使用工具默认缓存位置，仓库不保存它们的缓存目录。
